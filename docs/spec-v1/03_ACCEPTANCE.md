# 個人項目管理平台第一版驗收清單

版本 1.0 · 2026年11月1日 · 對應 01_SPEC.md

本清單交給開發助手逐項執行，確認第一版的實際行為。它是待執行的驗收要求，不表示軟件已通過測試。測試資料全部使用虛構人物、職位、課程和文件連結；測試、示範與正式資料庫必須分開。

## 驗收層級與完成規則

- **P0 必須通過**：身份驗證、資料完整性、持久化、日期正確性、備份還原及部署邊界。任一失敗都阻擋正式上線。
- **P1 必須通過**：第一版承諾的功能與主要操作流程。任一未完成都不能宣稱第一版完整交付。
- **單元測試**：日期運算、驗證及純業務規則。使用固定時鐘，避免依賴測試當天。
- **整合測試**：真實 PostgreSQL、migration、API、交易、Session 和並行寫入。不得以記憶體物件或 SQLite 代替 PostgreSQL 後宣稱通過。
- **端到端測試**：瀏覽器操作實際前後端，覆蓋登入、新增、編輯、導航、錯誤與重新整理。
- **部署驗證**：容器重建、volume、HTTPS、環境變數和 CI。在測試環境執行，不連正式資料庫。

每項結果只可寫「通過／失敗／未驗證」，並附實際命令或操作、測試環境及證據位置。沒有 Docker、PostgreSQL、瀏覽器或雲端測試環境時，相關項目寫「未驗證」及原因；不得改用程式碼閱讀、截圖、mock 或未執行的測試檔充當通過。供應商未指定不阻擋本機工程交付，但正式雲端連通、TLS 和部署結果仍須保留為未驗證。

## 啟動 身份驗證與持久化

### A01 乾淨環境初始化

P0 · 整合測試及端到端測試

**Given** 一個空白測試 PostgreSQL、有效的擁有者密碼雜湊及 Session 密鑰，且未執行 demo 指令。

**When** 執行 migration、啟動應用並登入。

**Then** 七個固定領域各出現一次，主鍵符合規格；任務、人物、申請及健康紀錄為空，空狀態可操作。重跑 migration 及重啟不重複領域、不注入 demo，不覆寫已有資料。

### A02 PostgreSQL 寫入與服務重啟

P0 · 整合測試及端到端測試

**Given** 已登入，建立一個項目、一個無日期任務及一個有日期任務。

**When** 重新整理、登出再登入、停止並重啟 API，再以全新瀏覽器工作階段讀取。

**Then** UUID、標題、日期、狀態及關聯完整保留；直接查詢測試 PostgreSQL 可找到相同資料。清除瀏覽器 localStorage 後業務資料仍在，不依靠前端假資料恢復畫面。

### A03 擁有者設定缺失與示範資料隔離

P0 · 整合測試及部署驗證

**Given** 分別缺少 ADMIN_PASSWORD_HASH 或 SESSION_SECRET 的環境，以及一個標為正式用途的資料庫。

**When** 啟動正式模式，或對該資料庫執行 db:seed:demo。

**Then** 缺少設定時明確啟動失敗，不提供預設密碼或 demo 登入；demo 指令拒絕正式資料庫。日誌不回顯原始密碼、雜湊或密鑰。只有明確指定的獨立 demo/test 資料庫可產生虛構資料。

### A04 未登入的 API 存取

P0 · 整合測試

**Given** 資料庫有虛構私人紀錄，請求不帶 Session 或帶無效 Session。

**When** 直接請求清單、詳情、搜尋、總覽、日曆、文件、設定、匯出及全部改寫 API。

**Then** 受保護端點回401，無正文、數量或存在與否等私人資訊外洩；公開 healthz/readyz 只提供服務狀態。未知路由不能藉 SPA fallback 回傳私人資料。

### A05 Session 生命週期

P0 · 整合測試及端到端測試

**Given** 正確密碼可登入，測試可控制時間，正式模式經 HTTPS 提供服務。

**When** 檢查登入 Cookie，繼續操作、模擬七日閒置、登出，並另行變更 ADMIN_PASSWORD_HASH 後重啟。

**Then** 登入會更新 Session ID；正式 Cookie 有 HttpOnly、Secure、SameSite=Lax 及 path=/。閒置到期、登出及憑證變更後舊 Session 不能讀寫；瀏覽器收到401會清理私人快取並回登入頁，沒有假成功提示。

### A06 Origin CSRF 與登入限流

P0 · 整合測試

**Given** 正常同來源請求可登入和改寫。

**When** 以外部 Origin 登入／改寫、以有效 Session 但缺少或偽造 CSRF token 改寫，並超過登入失敗次數上限。

**Then** Origin／CSRF 不符回403且資料不變；超額失敗登入回429。按部署設定測試可信代理層數，偽造轉發標頭不能任意改變限流身份；錯誤和日誌沒有憑證內容。

## 任務 項目與日期

### A07 只輸入標題的收件箱任務

P1 · 整合測試及端到端測試

**Given** 收件箱為空。

**When** 只輸入「閱讀方法論文章」並儲存，重新整理，再到所有任務選擇「無日期」。

**Then** 同一筆未分類任務同時可在收件箱及所有任務找到；沒有被補上今天或1970年日期。選擇領域後離開收件箱、保留原 UUID；完成或取消後不再出現在未完成收件箱。

### A08 項目領域繼承與移動

P0 · 整合測試及端到端測試

**Given** 一個 general 項目屬於學業，其任務有 project_id 且 area_id 為空。

**When** 將項目移到外展領域，再解除其中一個任務與項目的關聯。

**Then** 所屬任務的有效領域即時隨項目改變，各頁和總覽一致；解除關聯的任務保存解除前主領域，不掉回收件箱。API 拒絕同時指定 project_id 和 area_id，並拒絕把 degree_application 移到不允許的領域。

### A09 提交任務 申請階段與回執

P0 · 整合測試及端到端測試

**Given** 一個 preparing 申請，提交日空白、receipt_verified=false，並有「提交申請」任務。

**When** 完成該任務，再手動把申請改為 submitted；最後主動填入實際提交日並確認回執。

**Then** 完成任務不改申請階段；submitted 不把項目變成完成，不自動填今天或核實回執。每次階段改動僅有一筆正確歷史，與狀態同一交易保存。closed 要求有效結果；關閉／重開依規格同步項目狀態，不代替使用者完成其他任務。

### A10 香港午夜與只有日期的截止

P0 · 單元測試及整合測試

**Given** due_on=2026-11-01 的待辦，API 主機時區分別設 UTC 及其他時區。

**When** 將固定時鐘依次設為 2026-11-01T15:59:59Z 和 2026-11-01T16:00:00Z。

**Then** 兩時點在香港分別為11月1日23:59:59及11月2日00:00:00；前者未逾期、後者逾期。伺服器 today 與各介面一致，due_on 經資料庫、API、匯出／匯入後仍為2026-11-01。done/cancelled 任務在兩時點均不列入逾期。

### A11 精確截止時間與原始時區

P0 · 單元測試及整合測試

**Given** due_at=2026-11-01T09:00:00Z、due_timezone=Asia/Hong_Kong 的任務，另有 only planned_on 及 only follow_up_on 任務。

**When** 固定 now 為截止前、剛好截止及截止後一秒，並提交 due_on 與 due_at 同時有值的請求。

**Then** 只在 now > due_at 時逾期，顯示原始香港時間17:00；日期互斥請求回400。執行日和跟進日不被當成截止；空日期維持空值。另用一個有夏令時間的 IANA 時區驗證由輸入時區轉換成正確時間點。

### A12 總覽範圍 與日曆去重

P0 · 單元測試及整合測試

**Given** 固定香港今天為2026-11-01星期日；準備同日安排兼截止、不同日安排／截止、跨週活動及七日邊界資料。

**When** 查看今日、本週、未來七日、等待跟進及日曆。

**Then** 本週為10月26日至11月1日；未來七日為11月1日至7日。今日同一任務只出現一次並保留兩種原因；不同日期可分別出現但都編輯原資料。到期跟進優先，無日期等待事項仍可找到；衍生提示不增加 tasks 筆數。

### A13 每日最多三項重點

P1 · 整合測試及端到端測試

**Given** 同一香港日期已有兩項重點，兩個瀏覽器分頁使用相同初始資料。

**When** 並行嘗試各加一項，並測試重排、重複 taskId、完成其中一項及切換到翌日。

**Then** 同一天永遠最多三項、位置不重複；衝突請求回409而非寫入第四項。重複 ID 明確拒絕；完成項保留於該日且顯示完成，翌日沒有自動複製。

### A14 欄位驗證與文字處理

P0 · 單元測試及整合測試

**Given** 各主表均可正常新增。

**When** 分別提交空白標題、超長內容、非法 enum、未知欄位、不存在外鍵、重複／超量標籤、非法日期及帶 HTML/script 的備註。

**Then** 格式或關聯錯誤明確拒絕，現有資料不變；標籤依規格去重。合法文字內容以文字顯示，script 不執行，SQL 特殊字元不能改變查詢含義；錯誤指出對應欄位而不回傳堆疊。

### A15 一般並行更新衝突

P0 · 整合測試及端到端測試

**Given** 兩分頁讀取同一 version 的任務。

**When** 分頁甲先保存修改，分頁乙用舊 version 保存另一內容。

**Then** 甲成功且 version 更新，乙回409並保留尚未保存的輸入。介面提示重新載入，資料庫維持甲的內容；乙重新讀取、明確編輯後才可更新。總覽和日曆不長期停留在舊快取。

## 活動 人物 文件與健康

### A16 活動報名與出席分開

P1 · 整合測試及端到端測試

**Given** 一個有報名截止的 interested 活動，attendance_status=planned。

**When** 報名狀態依次改為 applied、confirmed、waitlisted，並在另一個測試資料改為 rejected；之後單獨登記出席。

**Then** applied 不等於 confirmed，任何報名變更不自動標為 attended。已報名／確認／候補不再出現報名截止提醒，活動仍可查到；已出席或取消不列入待辦提醒。介面清楚顯示兩種狀態。

### A17 全天與跨日活動

P0 · 單元測試及整合測試

**Given** 全天活動 start_on=2026-11-01、end_on=2026-11-02，及跨香港午夜的定時活動。

**When** 查看各日、月曆和本週議程，編輯保存，再提交結束早於開始或兩種日期欄位混用的活動。

**Then** 全天活動涵蓋1日及2日、不延伸至3日；跨日活動按區間重疊出現且只有一筆原始紀錄。定時活動保留時間點和時區；無效時間或欄位組合被拒絕。

### A18 多領域關聯不複製資料

P1 · 整合測試及端到端測試

**Given** 一個香港求職項目關聯申博領域，一場活動關聯兩領域，一位聯絡人及一份文件分別關聯多個對象。

**When** 從不同入口查看、修改及解除其中一個關聯。

**Then** 各入口使用同一 UUID，修改同步反映，全局計數不重複。解除關聯只移除關係，不刪除人物、文件、項目或活動；重複關聯及不存在的外鍵被拒絕。

### A19 人物互動與聯絡提醒

P1 · 整合測試及端到端測試

**Given** 一位聯絡人已有下一次聯絡日期，並關聯學業及申博項目。

**When** 新增一筆過往互動和一筆較新互動，再修改其中一筆的發生時間及摘要。

**Then** 時間線按實際 occurred_at 排列，最近互動依有效紀錄計算；聯絡提醒保留至使用者明確清除或改期，不自動猜測下一次日期。所有項目指向同一人，沒有自動發信或關係分數。

### A20 習慣頻率 冪等打卡與歷史

P0 · 單元測試及整合測試

**Given** 一個每週星期一、三、五的習慣，另有每日習慣，且均有開始日期及既有打卡。

**When** 連點或並行 PUT 同一習慣同一日、改成 skipped、清除，再更改未來頻率；另測試補記、未來日及開始前日期。

**Then** 每個 habit_id + local_date 最多一筆，沒有重複計次。補記允許的過往未排定日可保存，但不被改稱原計劃必做日；未來／範圍外日期被拒絕。修改頻率不改既有記錄，不生成無限任務，也不偽造歷史完成率或連續天數。

### A21 運動與睡眠紀錄

P1 · 整合測試及端到端測試

**Given** 同一日期尚無健康紀錄。

**When** 新增兩筆不同運動、一筆睡眠，再新增第二筆睡眠、負數時長、超過24小時睡眠及無備註的 note；另完成一個運動習慣打卡。

**Then** 同日兩筆運動可保存，睡眠最多一筆並以醒來當日顯示；非法值明確拒絕。打卡不自動增加運動紀錄，修改健康紀錄也不擅自改習慣。

### A22 文件連結與本機路徑

P0 · 整合測試及端到端測試

**Given** 一個 http/https 文件連結和文字路徑 C:\Example\CV.pdf。

**When** 儲存、複製、關聯到多個項目，嘗試 javascript/file 等不允許的 web_link 協定及不存在的本機路徑。

**Then** web_link 協定受到驗證；本機路徑僅保存和複製文字，不呼叫伺服器讀檔、不宣稱可讀，也無任意檔案端點。路徑失效不刪紀錄；介面及匯出頁清楚表示備份不包含連結指向的實體文件。

### A23 封存與恢復

P0 · 整合測試及端到端測試

**Given** 一個項目有未完成任務、已完成任務、相關人物及獨立活動，另有獨立封存任務。

**When** 封存項目、查看日常清單和封存區，再恢復項目；另對獨立任務、人物、文件及習慣執行封存／恢復。

**Then** 項目封存前顯示影響提示；其任務暫從日常清單隱藏，恢復後保持原狀，原先獨立封存任務仍封存。人物及獨立活動不隨項目消失；恢復不複製 UUID。單純 completed 項目下未完成任務仍能找到，UI 不提供靜默永久刪除。

### A24 搜尋 篩選與清單狀態

P1 · 整合測試及端到端測試

**Given** 各類實體含長中文、英文大小寫、標籤、長網址、無日期和封存資料，總數足以分頁。

**When** 搜尋名稱／機構／職位，組合領域、狀態、標籤及無日期篩選，改變 limit/offset，並搜尋不存在的字串。

**Then** 結果類型和領域清楚，點擊開原始資料；分頁無重複或遺漏，limit 大於200受到限制，排序欄位採白名單。預設排除封存，明確切換後可找到；空結果和載入失敗不同，不展示假資料。

## 備份 還原與一致性

### A25 匯出內容完整且排除系統秘密

P0 · 整合測試

**Given** 每種業務實體及關聯都有虛構資料，包含封存、申請歷史、每日重點、習慣與健康紀錄；系統另有有效 Session。

**When** 下載備份並解析 JSON。

**Then** format、schemaVersion、appVersion、exportedAt、timezone 和全部業務資料齊備，UUID、日期、版本及關聯一致，包含focus_days。檔名使用香港時間；Session、密碼、密鑰、migration、system_state、還原 token 和實體附件均不在備份中。

### A26 無效備份完全不改資料

P0 · 整合測試

**Given** 已保存目前業務資料的排序後快照及 revision。

**When** 分別預覽損壞 JSON、未知版本、重複 ID、孤立外鍵、無效日期、缺少固定領域、違反唯一約束及超過20MB的檔案。

**Then** 每個檔案均被明確拒絕，過大回413，其餘給可理解的驗證錯誤；業務快照與 revision 完全不變，不能先寫有效部分再報錯，亦不產生可使用的還原 token。

### A27 匯出期間的一致性快照

P0 · 整合測試

**Given** 申請階段及歷史必須同一交易更新，並準備可控制交易時序的測試。

**When** 在改寫執行期間觸發匯出。

**Then** 備份反映改寫前或改寫後的一致狀態，不出現新階段配舊歷史、缺失外鍵或部分關聯。將該備份送入 preview 可通過完整驗證。

### A28 還原預覽與確認條件

P0 · 整合測試及端到端測試

**Given** 一份有效備份已預覽，得到綁定 Session、檔案雜湊、目前 revision 及到期時間的 token。

**When** 分別用不同 Session、變造檔案、超過10分鐘、錯誤密碼、未輸入「還原」、未完成現況備份下載請求嘗試還原；另在預覽後正常新增一筆業務資料再還原。

**Then** 所有不符合確認條件的嘗試均拒絕且業務資料不變；預覽後資料變動回409要求重新預覽。頁面顯示會被取代的範圍及筆數，並只宣稱已提供備份下載，不宣稱核實磁碟檔案。

### A29 還原失敗的原子回復

P0 · 整合測試

**Given** 有效預覽及確認流程已完成，目前業務資料有已知快照。

**When** 透過測試專用故障注入，在刪除後、插入中及提交前分別製造交易錯誤；同時嘗試一般業務改寫。

**Then** 還原失敗全部 rollback，業務資料和關聯維持原狀，沒有半空資料庫；寫入鎖協定避免其他寫入混入還原。API 回傳失敗而非成功，不把故障注入入口帶進正式版。

### A30 新資料庫的完整還原往返

P0 · 整合測試及端到端測試

**Given** 來源測試資料庫包含 A25 的完整資料；目標為只完成 migration、七領域及獨立登入設定的新資料庫。

**When** 從來源匯出，在目標登入、預覽、下載現況、確認還原，重新登入後再匯出。

**Then** 排除 exportedAt 等匯出包裝資訊後，全部業務表筆數、UUID、欄位、日期、封存、歷史及關聯與來源一致。目標使用自己的登入秘密，不匯入來源 Session；系統 revision 不接受備份指定。重複整體還原不累加紀錄。

### A31 還原後的舊分頁不可覆蓋

P0 · 整合測試及端到端測試

**Given** 分頁甲保留未儲存表單與舊 version/workspaceEpoch，分頁乙成功還原；備份刻意含有與舊表單相同 UUID 及相同列 version，另有已通過中介層但仍在等待寫入鎖的舊請求。

**When** 甲直接提交，再重新登入後仍嘗試送出先前表單。

**Then** 舊 Session 首先被拒絕；重新登入也不能因列 version 碰巧相同而覆蓋還原結果。舊 workspaceEpoch 的寫入回409並要求重新讀取；排隊請求取得鎖後重驗epoch，亦不可落庫。前端清除舊查詢快取；還原後的新資料保持完整。

### A32 容器重建與 PostgreSQL 持久化

P0 · 部署驗證

**Given** 本機 Compose 使用有名 volume，已保存虛構業務資料及完成 migration；另有可用的雲端測試部署時一併驗證。

**When** 重啟應用、重建應用映像及重新建立容器；在不刪除 volume 的情況下重建資料庫容器。

**Then** 業務資料仍在，登入 Session 依規格存活或失效，無 demo 或 reset 覆寫。應用非 root 運行、DB 端口本機只綁127.0.0.1或在私人網絡、正式流量使用HTTPS；資料庫連線遵循供應商 TLS 設定，不默認停用憑證驗證。未實際部署的雲端部分標為未驗證。

### A33 GitHub 檔案與 CI 隔離

P0 · 靜態檢查及 CI 實際運行

**Given** 專案有 .gitignore、.dockerignore、鎖檔、migration、CI 及只有 placeholder 的 .env.example。

**When** 用虛構檔名測試忽略規則，檢查 staged 檔案清單／diff、建置上下文和前端 bundle，再執行 CI。

**Then** .env 及變體、個人備份／dump、真實文件、Session、報告及截圖不被納入 Git 或容器；.env.example 正常保留，前端無伺服器秘密。CI 使用臨時 PostgreSQL 和測試憑證，實際完成 npm ci、型別、lint、單元／整合測試、build 及至少一個 Playwright 核心流程。沒有遠端 CI 執行證據時只記本機檢查通過，CI 記未驗證。

## 驗收紀錄格式

每個案例用以下格式追加到實際工程的 docs/BUILD_LOG.md 或獨立驗收報告，不要預填通過：

```text
A01
結果：通過／失敗／未驗證
環境：commit、Node 版本、PostgreSQL 版本、資料庫用途、瀏覽器或容器環境
執行：實際命令或操作步驟
證據：測試輸出、CI run、截圖或可重現記錄
差異及下一步：實際缺口；若未驗證，寫缺少的條件
```

所有適用於本機的 P0 與 P1 均有通過證據，才可把本機第一版標示為完成。A05、A32、A33、A35 中需要真實雲端／遠端CI的部分獨立列出，尚未部署或推送時保留未驗證，不因此捏造成功；正式上雲完成需補齊這些證據。修復失敗後重跑相關案例及受影響流程，不以未受影響的重複測試取代必要驗證。
